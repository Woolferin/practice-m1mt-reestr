# Специфікація вимог (Requirements Specification)

## 1. Призначення системи
Система «Електронний реєстр звернень» є веб-орієнтованим програмним продуктом, розробленим для автоматизації процесу збору, просторової прив'язки та базового управління зверненнями громадян щодо об'єктів благоустрою.

## 2. Функціональні вимоги (Functional Requirements)

### 2.1. Клієнтська підсистема (Модуль заявника)
* **FR-1.1:** Система повинна надавати інтерфейс (HTML-форму) для введення текстових даних: ПІБ, категорія звернення, адреса та детальний опис.
* **FR-1.2:** Система повинна містити інтерактивний картографічний модуль для просторової ідентифікації інциденту.
* **FR-1.3:** Система повинна автоматично зчитувати координати (широту `lat` та довготу `lng`) при взаємодії користувача з картою (клік) та приховано передавати їх до сервера.
* **FR-1.4:** Система повинна здійснювати базову клієнтську та серверну валідацію, блокуючи відправку форми у разі відсутності текстових даних або координат.

### 2.2. Адміністративна підсистема (Модуль обробки)
* **FR-2.1:** Система повинна генерувати зведений реєстр усіх звернень у вигляді таблиці, сортуючи їх за часом надходження у зворотному хронологічному порядку (найновіші зверху).
* **FR-2.2:** Система повинна формувати гіперпосилання для кожного звернення (за наявності координат), яке дозволяє відкрити локацію в сервісі OpenStreetMap.
* **FR-2.3:** Система повинна надавати механізм (випадаючий список) для зміни статусу життєвого циклу звернення («Нове», «В роботі», «Вирішено»).
* **FR-2.4:** Система повинна автоматично зберігати новий статус у базі даних при його зміні в інтерфейсі без необхідності ручного перезавантаження сторінки (через відправку форми на подію `onchange`).

## 3. Нефункціональні вимоги (Non-functional Requirements)

### 3.1. Вимоги до технологічного стеку та інфраструктури
* **NFR-1.1:** Серверна частина додатка повинна бути розроблена мовою PHP (рекомендовано версію 8.0+).
* **NFR-1.2:** Для збереження даних повинна використовуватися реляційна СУБД MariaDB (або сумісна MySQL-база).
* **NFR-1.3:** Додаток повинен розгортатися у середовищі Linux під управлінням веб-сервера Apache.

### 3.2. Вимоги до безпеки (Security)
* **NFR-2.1:** Усі транзакції до бази даних повинні виконуватися виключно через інтерфейс PDO з обов'язковим використанням параметризованих (підготовлених) запитів для повного виключення вразливостей типу SQL Injection.
* **NFR-2.2:** Усі текстові дані, отримані від користувача, повинні проходити санітизацію під час збереження (`trim()`) та екранування спеціальних символів під час виведення в адміністративній панелі (`htmlspecialchars()`) для захисту від міжсайтового скриптингу (XSS).

### 3.3. Зовнішні інтеграції та обмеження
* **NFR-3.1:** ГІС-компонент повинен бути реалізований за допомогою відкритої бібліотеки Leaflet.js.
* **NFR-3.2:** Джерелом картографічних тайлів повинен виступати відкритий сервіс OpenStreetMap, що виключає необхідність використання платних API-ключів (наприклад, Google Maps API).
