# План подальшого розвитку (Roadmap)

Цей документ визначає стратегічні напрямки вдосконалення системи «Електронний реєстр звернень» для її переходу від стадії прототипу (MVP) до повноцінного комерційного або муніципального продукту.

## 1. Посилення безпеки та розмежування доступу
* **Автентифікація адміністраторів:** Впровадження системи ідентифікації (логін/пароль) для захисту доступу до панелі управління `admin.php`. Використання безпечних сесій PHP або архітектури JSON Web Tokens (JWT).
* **Хешування:** Застосування алгоритмів надійного криптографічного хешування (наприклад, bcrypt) для зберігання облікових даних адміністраторів у базі даних.
* **Захист від CSRF:** Додавання унікальних токенів у форми для запобігання атакам підробки міжсайтових запитів (Cross-Site Request Forgery).

## 2. Розширення картографічного та аналітичного функціоналу (ГІС)
* **Просторові бази даних:** Міграція від зберігання координат у базовому форматі `DECIMAL` до спеціалізованих просторових типів даних (MySQL Spatial Extensions або міграція на екосистему PostgreSQL + PostGIS).
* **Просторова аналітика:** Реалізація функціоналу фільтрації звернень за географічними полігонами (наприклад, вибірка інцидентів виключно в межах певного міського мікрорайону).
* **Теплові карти (Heatmaps):** Впровадження візуалізації концентрації інцидентів для виявлення проблемних зон міста, що допоможе комунальним службам оптимізувати маршрути реагування.

## 3. Модернізація інтерфейсу та роботи з даними
* **Завантаження медіафайлів (File Upload):** Додавання функціоналу для прикріплення фотографій об'єктів благоустрою із суворою перевіркою типів файлів (MIME-types) та обмеженням їхнього розміру.
* **Автоматизовані сповіщення:** Інтеграція SMTP-сервера або API месенджерів (наприклад, Telegram Bot API) для автоматичного інформування заявників про зміну статусу їхнього звернення.
* **Експорт даних:** Створення модуля генерації звітів із можливістю вивантаження відфільтрованих даних у формати CSV або Excel.

## 4. Оптимізація інфраструктури (DevOps)
* **Контейнеризація:** Переведення інфраструктури на Docker (створення файлів `Dockerfile` та `docker-compose.yml`) для ізольованого середовища розробки та миттєвого розгортання системи на будь-якому сервері без необхідності ручного налаштування Apache та MariaDB.
* **Тестування:** Впровадження модульного тестування (Unit Testing) за допомогою фреймворку PHPUnit для перевірки надійності логіки обробки вхідних даних.
